# Developing Pallot

What the code can't tell you: the commands, how the tests are set up, what the outside sources do, and the checklists for adding things. To run Pallot, see the [README's quick start](README.md#quick-start). The rules for a change (branches, commits, what Pallot must never do, which docs to update) are in [AGENTS.md](AGENTS.md).

This is not a walkthrough of the code. Don't describe modules, functions, fields or UI behaviour here: they change with every feature and the code already says them. Put the why of a function in its docstring. Add to this file only when a source's behaviour, a command or a checklist changes.

Pallot is one Python process (FastAPI) serving a plain HTML/JS page from `pallot/static/`. There's no frontend build step and no database server: everything it keeps is files in `data/` (the cache is SQLite, `data/cache.sqlite3`).

The pages load their scripts, styles and icon from `/s/<stamp>/`, a hash of the static files taken at startup, and the browser keeps those a year without asking. Every import is relative, so the whole module graph follows the stamp. Keep it that way: a URL starting with `/` in a module or stylesheet skips the stamp (use `new URL("../x", import.meta.url)`). The pages and the files' own addresses are checked before each use. A browser that kept a static file sees an edit to it only after the server restarts; `--reload` restarts on those too.

## Commands

`uv sync` installs Pallot with the dev tools (pytest, pytest-xdist, respx, ruff), pinned by `uv.lock`.

```bash
uv run pallot --reload                    # restart on code and static file changes
uv run pytest                             # offline: recorded responses in tests/fixtures, plus trackaipac_cache's, voteforpeace_cache's and tec_cache's own tests
uv run pytest -n 0 --pdb                  # the same in one process, to use the debugger or see print()
uv run pytest -m live                     # smoke tests against the real services (the FEC one needs an FEC key)
uv run ruff check                         # pyflakes (unused imports and variables, undefined names) and syntax errors
uv run pallot-cache check                 # what data/ keeps, and what's stale (also refresh, prune, hard-refresh, rebuild)
uv run python scripts/record_fixtures.py  # re-record tests/fixtures from the live APIs (--only ballots|suggest|fec|nationwide|state_lists|grid|polls|key_dates|officeholders|congress_gov|wikidata|tigerweb|election_precincts|county_precincts|endorsement_feeds|tec|trackaipac|voteforpeace)
uv run pallot-bundle refresh              # rebuild the bundled answers in bundles/data (--only, --due, --dry-run, --force)
uv run pallot-bundle stats                # the snapshots' counts, as README's "What the snapshots hold"
```

## Tests

- **In parallel.** `pytest-xdist` runs one worker per CPU (`-n auto --dist loadgroup`). Each test has its own data folder under `tmp_path`.
- **The live tests, one at a time.** They share one worker (`xdist_group("live")`), so a real service never gets two calls at once.
- **No throttling waits.** The tests' `make_app` passes `min_interval={}`; `test_calls_to_one_source_are_spaced_out` checks the throttling itself.
- **Sources on.** Tests see the shipped defaults (`pallot/sources.toml`), so every source starts on unless a test switches it. `switch(client, id, on)` flips a source for that client's later requests, by the header the page sends.
- **`make_app` allows `testserver`**, TestClient's host name, past the Host middleware.
- **As Pallot's pages.** `/api/*` answers only Pallot's own pages, so `conftest.py`'s autouse `as_pallots_pages` gives every TestClient the headers the page sends (`Sec-Fetch-Site: same-origin` and `X-Pallot-Sources`). A test of other callers changes or deletes them.
- **pallot-cache beside the app.** `make_app.cache_command("refresh", "sos")` runs `maintain.run` on the test's data folder, as the command does beside a running server, and returns the exit status and what it printed.
- **Made-up maps.** `conftest.py` makes the SBOE map and the precinct map (a shapefile in EPSG:3081 with the real `.prj`). Every exact fixture address's two points fall in one precinct; the rest cover the awkward shapes (a precinct in two pieces, a hole another fills, overlaps, a shared edge). Only the live test downloads the real 45 MB map. `record_fixtures.py --only election_precincts` records the portal's index, never the map.
- **Made-up county lists.** `Upstream.arcgis` serves Travis's and Harris's servers from recorded service lists, with the lists themselves made up from the made-up map's precincts, since a county's list must match the map exactly.
- **No bundles, no SBOE map** unless a test asks (`make_app(bundles=…)`, `make_app(sboe_bundled=…)`). Any other `Config` field goes in by name too (`make_app(rate_limits=…)`).
- **Rate limits.** TestClient's client isn't an IP address, so the default limits apply to every test, and leave room for them. A test of the limits sets tight ones, and wraps the app in uvicorn's `ProxyHeadersMiddleware` to ask as different visitors through `X-Forwarded-For`.
- **Ballots outside Texas.** `record_fixtures.py --only nationwide` records a few addresses in states without their own list, the FEC's lists of the cycle's seats and those seats' filers, which are those ballots, and adds those states' members of Congress to the seat holders. A state with its own list records its own (`state_lists`, `state_<st>`).
- **Google** has no recorded fixture (it needs a key): `Upstream` answers it with made-up results.
- **Front end.** `tests/test_frontend_modules.py` follows each page's imports: every module must be served and every imported name exported, since a wrong import name blanks a page without failing anything else. Tests of the JS logic run it in Node and are skipped where `node` isn't installed; GitHub's runners have it.

## The cache's rules

Beyond AGENTS.md's "Every outbound call goes through `HttpCache`":
- Only answers that succeed are cached, and concurrent identical requests share one fetch.
- Expired rows stay, as the copy to serve when a source is down. Only transient rows (address suggestions, tiles, "not found" geocodes, expired flags) are ever pruned, after `Ttls.prune_after`, and tiles, suggestions and each geocoder's answers are kept under their size caps, oldest first.
- A source that costs money (Google, and the suggestions from it) is held to so many requests a day with `cap_daily`, then paused until midnight UTC. Each request sent is a flag that expires then, so the count survives a restart.
- Some sources answer an error with a 200 (ArcGIS servers, a maintenance page). Such a source registers a check with `check_answers`, so a refused answer never replaces a good copy. The check runs on every `get_json`, cache hits included, on the event loop, so a costly one remembers its verdict per stored copy: `HttpCache` hands back the same object while it keeps that copy in memory (a live endorsement feed parses each copy once, and builds its list from that parse).
- SQLite runs in WAL mode with `synchronous=NORMAL`: a write isn't synced to disk each time, and a power cut can lose only the last writes, never corrupt the cache.
- A file too big for the database (the precinct and SBOE maps) goes through `HttpCache.download`: the same pause, throttle and call count, but nothing stored.
- A source with several keys (the FEC) registers them with `share_keys`: requests rotate over the keys with room, a key the source refuses rests for a while (flagged by a hash, never the key), and inside `offline()` (`pallot-cache refresh`, `pallot-bundle refresh`) each key goes at the slower `refresh_limit`, leaving room for a running Pallot.
- `/api/ballot` streams two NDJSON lines to the page: the races, then the ballot with its cards. Every `BallotError` is raised before the first line, so it's still an HTTP status.

## What the sources do

What each outside service does that the code has to work around. AGENTS.md's "Be gentle with the sources" has the rules that follow from them (Nominatim, FiftyPlusOne's headers, TEC's zip, OpenStreetMap's tiles, the precinct map).

- **Census geocoder:** already on the 2026 maps, but for Missouri's U.S. House districts: its "120th" map is the 2025 one, which a referendum petition held back, and the Missouri Supreme Court kept the 2022 map for 2026. That map is TIGERweb's `tigerWMS_ACS2024` "119th Congressional Districts", so a Missouri address's district is one `identify` call there at its point, kept with the address lookup's, and its outline comes from there too. Its `2020 Census Blocks` give each address's block point, used as the second point in the precinct check. Its districts lookup (`/geographies`) can fail with a 502 while its plain one (`/locations`) still answers. Then the address's point comes from `/locations`, and the districts from one TIGERweb `identify` call at that point. The layers and fields are the same, and the answers are kept per point with the address lookup's. A lookup that was placed this way skips `/geographies` the next time, so it makes no calls.
- **Google Geocoding (v4):** takes the key in the `X-Goog-Api-Key` header. Answers are kept 30 days, the most Google's terms allow for coordinates. It's `refreshable=False`: a refresh would re-send every saved address to a billed API.
- **Google Places Autocomplete (New):** the address suggestions, with the geocoding key in the same header (the Places API must be enabled for it). Only street addresses (`includedPrimaryTypes`) in the US, and nothing is sent before a house number and three more characters. Without a key, `/api/suggest` says suggestions are off and Settings leaves the row out.
- **SBOE map (PLANE2106):** comes with Pallot (`pallot/data/plane2106_kml.zip`) and has no lifetime: the plan holds until the next redistricting. Then replace the zip with the new one (and `KML_URL`), and check it with `read_download`.
- **TLC precinct maps** (CKAN `precincts` dataset on data.capitol.texas.gov): the newest map is the SHP zip ranked by the year in its description, then a general's over a primary's, then `created`. A primary's map serves its general: the TLC publishes a general's only afterwards, and counties can only redraw precincts in March or April of odd years (Election Code §42.031); 99.5% of precincts carried over in 2022, 99.9% in 2024. The server ignores `Range`. `CNTY` is the county's FIPS code, not the SOS's alphabetical number; `PREC` is the county's own name for the precinct (`0300`, `101A`, `03-3`). The projection is EPSG:3081; any other is refused.
- **Counties' precinct records** (Election Code §42.005 puts each election precinct inside one commissioner and one JP precinct):
  - Lists: Harris (`VPCT_txt`, `Comm__Cour`, `JP_Constab`), Dallas (`NewPrcnt`, `Comm`, `JP`), Tarrant (`Pct_Char`, `Commish`, `JP`), Travis's Tax Office (`Precinct`, `Commissioner` as "P02", `JPConstable` as "J05"), Fort Bend (`PRECINCTID`, `COMM_PRECI`; its JP map isn't public). A list is used only when its precincts are exactly the precinct map's for the county.
  - Maps: Bexar and Denton. Denton's precinct layer has a `Comm` field, but it's the number's first digit, so Denton is read from its maps. Points 50 m in from the precinct's edges gave no wrong numbers against Dallas's and Harris's lists (10 m gave 3).
  - Dallas and Harris publish proposals beside the adopted precincts, so a name with "proposed" or "draft" is never taken. Git for Windows' curl rejects Tarrant's certificate chain; httpx accepts it.
  - ArcGIS answers errors with a 200 and an `error` body. All seven servers share one throttle and one pause.
- **TIGERweb:** its "Current" service names layers like the geocoder's ("120th Congressional Districts"), each with a "… Labels" twin, so a layer is found by the end of its name, newest vintage first. Districts are asked by GEOID (the state's FIPS code plus the number in 2 digits for Congress, 3 for the Legislature; DC's delegate is `98`), or by `STATE` and `BASENAME` where the district is a letter or a name, simplified on the server. Errors come as a 200 (`Layer not found`).
- **Texas SOS:** a county's ballot order lists only printed names; declared write-ins come from the statewide candidate list (`cdParty "W"`), which has no `nbOfficeTypeOrder` and no county for district judges and DAs. It answers a 5xx now and then, sometimes for more than ten counties in one build, so the build asks those again in two more rounds, 30 seconds apart.
- **SOS "Important Election Dates" page:** earlier years' tables are still in the page inside HTML comments; labels vary between tables, so a row is known by how its label starts; a date cell can add a footnote or time after the date. A maintenance page comes back as a 200 with no table.
- **FEC:** `/elections/` lists everyone who filed for a seat in a cycle, primary losers included, and nothing in OpenFEC says who is on a state's November ballot (`/candidates/` keeps losers "active" too). That's why a state without its own list gets the filers who raised $5,000 or more, each Unverified. `/elections/search/` names the cycle's seats: the Senate's is one page (specials included), the House's five (territories included, which Pallot drops). At-large seats and DC's delegate are district `00`.
- **State candidate lists:** each state's election office publishes its own, in its own form:
  - Michigan: one HTML report of state and judicial offices, a heading per office; county and local candidates file with the counties, so they aren't in it.
  - North Carolina: one CSV a year on S3, a row per candidate per county a contest reaches, primary and general together; no withdrawn candidates, write-ins or incumbents.
  - Pennsylvania: JSON in a hidden field of the Election Info page, everyone who filed for the year; a general's candidate won the primary or was nominated by papers.
  - Florida: a tab-separated extract asked for with the download page's form; only status `QUA` is on the ballot.
  - Virginia: HTML tables linked from the Department of Elections' Candidates & Referendums page, under names that change each year (2025's were `house-of-del`, `statewide-offices`, `local-offices` and `all-office`; 2026's `federal-offices`, `local-offices` and `all-offices`). Each party's candidates come under its heading ("REPUBLICAN CANDIDATES") in ballot order, an office's under its own ("For State Senator", without the "For" in 2024), a district's as "District 2, Name" and a circuit court's as "Circuit 19 Division 2, Name"; then the judges for retention. Text pages carry nothing else: no addresses, incumbents, write-ins or withdrawals (the Secretary of State's list of withdrawn candidates is the primary's). The Census names St. Louis County and St. Louis City alike, so their circuit courts' judges aren't placed.
  - South Carolina: the State Election Commission's candidate tracking (vrems.scvotes.sc.gov), in two steps as its page takes them: `GetElections?electionType=General&year=…` lists the year's statewide elections as JSON (the 2026 general is 22596), then a POST of the search form with that `ElectionId` and nothing chosen answers every candidate as an HTML table. No token or cookie is needed. Primary losers and the withdrawn stay on it under their status; only "Active" is on the ballot ("Elected" and "Defeated in Election" once it's over). It has no election date, write-ins, incumbents or contact details (those are in its CSV export, which isn't read). Each row names the counties its office reaches, empty for a statewide one; the county offices, school boards and special districts are named freely ("Fire District Commissioner, Jonesville"), and multi-seat races don't say how many seats, so only single-seat countywide offices and the solicitors are placed.
  - Kentucky: the Secretary of State's candidate filings (web.sos.ky.gov/CandidateFilings), an ASP.NET page whose dropdown lists its elections by name ("2026 General Election" is 87, "2027 Primary Election" 89). A postback of its "List All Candidates" button for an election, with the page's `__VIEWSTATE` and `__EVENTVALIDATION`, answers every office's candidates as HTML tables; an election with no candidates yet answers the page without them. A plain script gets a 200. Each row has the name (a Governor's running mate under it), a post office box or email, the office, the district and division as ordinals ("6th / 1st") and the party ("Nonpartisan" for the courts, "Write-In" for a declared write-in); the withdrawn, deceased and disqualified follow in their own tables. It has no election date, incumbents or ballot order (it's by name). The county offices are on a separate page (`countyfilings.aspx`), which isn't read.
  - Oklahoma: the State Election Board's list of elections (hosting.okelections.gov/electionlist.html), one static page for the next election day, its title naming the month and year (`NOVEMBER / 2026 List of Elections`). A plain script gets a 200; the filings portal (filings.okelections.gov) answers 403. It's county by county: each county's sections (`STATE OFFICERS`, `CONGRESSIONAL OFFICERS`, `LEGISLATIVE, DISTRICT AND COUNTY OFFICERS`, `JUDICIAL OFFICERS`, `JUDICIAL RETENTION`, `STATE QUESTIONS`, then each city's, town's or district's), each office's heading, and a line per candidate (`MIKE MAZZEI, REPUBLICAN`; judges without a party). A race comes under every county it reaches, which places a district judge's office (some are elected by one county of their district). Only contested races are on it, as on the ballot: an unopposed candidate is elected without a vote. The judges for retention are named only by their seat, so they aren't read. It writes `LEFLORE` for the Census's Le Flore County. It has no withdrawn candidates, write-ins, incumbents or contact details.
  - Kansas: the Secretary of State's candidate list (`elections_upcoming_candidate.aspx`), an ASP.NET page whose dropdown lists its elections by name ("2026 General" is 36, "2026 Primary" 35). A postback of the page for an election, with its `__VIEWSTATE` and `__EVENTVALIDATION`, `ddlElections` and its Submit button, answers one HTML table of every candidate; the page itself has no list. A plain script gets a 200. Each row has the name (a Governor's running mate after a slash), the office, its district, a judge's position and division ("0" for none), the party (empty for a judge standing for retention), then addresses, phones, emails and the filing date. It has no election date, incumbents, write-ins or withdrawn candidates. A State Board of Education district is four State Senate districts (K.S.A. 4-530 to 4-539), so it's placed by the Senate district. District magistrate judges serve one county the list doesn't name.
  - The raw files carry candidates' addresses and phone numbers, so only the parsed candidates are bundled.
- **FiftyPlusOne:** nationwide lists, 500 polls to a page, filtered to the ballot's state on the server (a poll names its state in full: "Texas").
- **Seat holders:** congress-legislators' `legislators-current.json` (every state) and Open States' `tx.csv`. A state has two senators: the one up is the one whose term ends by the January after the election, which also finds an appointee whose seat is up in a special election.
- **Congress.gov:** `/v3/member/{bioguide}/sponsored-legislation` and `/cosponsored-legislation`, newest first, with `pagination.count` the whole career's total (amendments included, which aren't listed). Takes an api.data.gov key in `X-Api-Key`; `DEMO_KEY` allows 10 requests an hour. Its member and bill pages redirect any name in the path to the right one. House votes come one roll call at a time (`/house-vote`) and there are no Senate votes, so a member's votes aren't read.
- **Wikidata:** path expressions, `GROUP_CONCAT` and the label service made the `PEOPLE` query time out, hence flat rows. Most Texas House members have no district on their position, so their seat is `STATEREP:*`. The query is one per state, by the state's Wikidata item; only Texas's own offices and Congress's seats are read as seats, so elsewhere a match for a state office is only likely. The list is everyone who held an office in the state, not candidates, so only a full-name or first-and-last match with no party against it counts.
- **Vote for Peace:** words offices its own way ("TX State Senator" with `sd-9`, "Harris District County Court Judge" with `228`); names the high courts without the place; files some county offices as statewide; some jurisdictions are cities. The page is a Next.js app: the data is read from its `self.__next_f.push` scripts, not the HTML.
- **Live endorsement feeds:** see [Live endorsement feeds](#live-endorsement-feeds).

## Adding a source

Each source contributes `SourceCard`s; the page draws them by `kind` (`money`, `polls`, `filing`, `profile` or `endorsement`). A new source needs:

1. A module in `pallot/sources/` that fetches through `HttpCache` and builds cards.
2. A field on `Services` in `ballot.py`, created in `open_services()` (`services.py`), which the server and `pallot-cache` share.
3. Its `cards()` in `JOBS` in `enrich.py`, placed where its tab goes in Details. It's asked only while the voter has the source on, with what the ballot found (`Context`). A source that knows only some states (TEC) names them in `ONLY_IN` (`coverage.py`), so it isn't asked about another state's ballot. A `cards()` without I/O runs through `asyncio.to_thread`. When it fails, it lets `UpstreamError` through: the voter gets its one fixed sentence in `UNAVAILABLE`, naming the source and what still works; the error itself goes to the server log, as do key names and anything the host should fix.
4. An entry in `SOURCES` in `catalog.py` so it appears in Settings and `pallot-cache`, under its `group`, and a line in `pallot/sources.toml` if it can be turned off. A source kept in files rather than cache rows names its `Services` field in `SourceInfo.kept` and implements `KeptSource` (`sources/__init__.py`).
5. For Help me pick's More conditions, `figures` and `flags` on its candidate cards. Sources that mean the same thing share an id (the FEC's and TEC's `raised`). `pick-rules.js` names the ids it knows.
6. For a money source, its Funding chips come from `highlights()` in `sources/highlights.py`.
7. Its throttle in `MIN_INTERVAL` (`services.py`), its pause (`pause_on`, which pauses on 403 and 429; pass only any other status it refuses with), and its lifetimes in `Ttls`.
8. Fixtures in `record_fixtures.py`, served by `conftest.py`'s `Upstream`, and tests with `respx`.
9. Rows in `static/privacy.html` and `static/about.html`, and an answer in `static/faq.html` if it raises a question.

## Adding a state's list

A state goes from Congress only (the FEC's filers) to its own official list with:

1. An adapter in `pallot/states/` that reads the list into one filing per candidate in a race, leaving out the withdrawn and disqualified, asked for through `HttpCache`, and its class in `ADAPTERS` (`states/adapters.py`). Its row in Settings and its bundle follow from that. Build it from the shared pieces in `states/__init__.py`: an `Office` per race (`us_senate`, `us_house`, `legislator`, `statewide`), `require` to refuse a list short of its races, `index_key` and `follow` for a list found through an index page first, `postback` for an ASP.NET form. A state on the shared `CandidateList.aspx` grid subclasses `GridList` (`states/grid.py`) and gives only its page, the query parameter naming the election, and its offices; a grid without an election dropdown also gives the page that links it (`index`).
2. Its entry in `COVERED` (`coverage.py`): which districts its races need. Every state already has its State Senate and State House districts, named in `CHAMBERS` where the state calls them something else.
3. Its key dates in its own module, beside the adapter: a `GUIDE`, which gives "When to vote" and the calendar file, and a `RULE` for its dates (a `Counts` when each deadline is a count of days before Election Day, a function when it isn't), with the law they're worked out from in the module's docstring. A `Counts` can have no registration deadline (`None`), move its deadlines past weekends and the state's holidays (`roll`), and open early voting the day after registration closes. A `Guide` can say who sets when the polls open, and that its hours are local time in a state of two time zones; `only_if` words absentee voting that needs an excuse, and `mailed_to_every_voter` a state that mails every voter a ballot. Then its line in `STATES` (`states/key_dates.py`). A state whose dates are read from its office's page keeps its `Guide` in `states/key_dates.py` and its page in `PAGES` instead.
4. Its switch in `pallot/sources.toml`.
5. Its fixture in `record_fixtures.py` (its own `--only state_<st>`, built from `record_census`, `record_filers`, `record_legislators` and `record_members`), and tests of the adapter and of a ballot there.
6. Run `uv run pallot-bundle refresh --only state_<st>` once and commit `bundles/data/`.
7. The state in README's "Where it covers" and "Bundled snapshots", About's "Where it covers" and Sources, the FAQ's "Which addresses and elections does Pallot cover?", and Privacy's list of what's downloaded whole.

The bundled lists keep each candidate's filing as it was read, so a list read before a new field on a filing doesn't have it, and reads as if it were off. With a new field, rebuild every list in the same change: `uv run pallot-bundle refresh --only state_<st> …` for the fetched ones, and save and import again those imported by hand. A test fails while a bundled list is missing one. A list imported by hand whose adapter never sets the field reads right without it, so it can wait for its next import: name it in the test's `PREDATES`.

## Endorsement lists

A frozen, one-time copy of an organization's list: one JSON file in `pallot/endorsements/`, found at startup. Each file becomes its own source (a switch, a card, a Help me pick Trust chip, a row on About and the FAQ) with no code naming it. Every state is kept; a lookup matches only its own state.

The file, `pallot/endorsements/<source>.json` (`parse()` checks it and refuses unknown fields):

| Field | Required | What |
|---|---|---|
| `source` | yes | the file's name without `.json`: lowercase letters, digits and `_`, starting with a letter, and not another source's id (`jvpaction`) |
| `label` | yes | the short name on badges, tabs and Settings (`JVP Action`) |
| `organization` | yes | its full name (`Jewish Voice for Peace Action`), also in its Settings line ("The candidates … endorses.") |
| `url` | yes | the http(s) page the list was copied from |
| `captured` | yes | the day it was copied, `YYYY-MM-DD` |
| `description` | yes | one sentence for the Details tab and the pages that name the lists |
| `candidates` | yes | at least one entry: |
| `candidates[].name` | yes | as the list writes it |
| `candidates[].state` | yes | two-letter postal code (`TX`); keep every state the list has |
| `candidates[].office` | yes | as the list words it; the seat is read from it: `U.S. Senate`/`U.S. Senator`, `U.S. House`/`U.S. Representative`, `State House`/`State Representative`, `State Senate`/`State Senator`, `State Board of Education`, `Supreme Court`, `Court of Criminal Appeals`, `Court of Appeals`, `District Judge`, the statewide offices (`Governor`, `Attorney General`, …), or `X County …` |
| `candidates[].district` | no | the district or place number, text or a number (`"35"`, `35`, `"sd-9"`), or `null` |
| `candidates[].jurisdiction` | no | the county a county or precinct office is in (`Travis`), the city for a city office (`Austin`), or `null` |
| `candidates[].party` | no | `Democrat`, `Republican`, `Libertarian`, `Green`, `Independent` (or `D`, `R`, …): a different party makes a match only likely |
| `candidates[].note` | no | the list's words on the candidate, shown in Details |
| `candidates[].url` | no | the candidate's own page on the list, the badge's link |

To add one:
1. Write `pallot/endorsements/<source>.json` from the list, by hand or with a one-off script you don't commit.
2. `uv run pytest tests/test_endorsements.py`: `test_every_list_that_comes_with_pallot_is_valid` fails on a malformed file and says where.
3. Run `uv run pallot`, look an address up, and check the cards, Settings, About and the FAQ.

## Live endorsement feeds

A list Pallot fetches from the organization's public JSON (`sources/endorsement_feeds.py`), one GET of the whole list, cached under the feed's id. Once fetched it behaves like a frozen list. A feed is a `Feed` in `FEEDS`:

| Field | What |
|---|---|
| `source` | its id: lowercase letters, digits and `_`, not another source's, list's or feed's (`mupac`) |
| `label` | the short name on badges, tabs and Settings |
| `organization` | its full name |
| `url` | the page people read the list on, the cards' link when an entry has no page of its own |
| `api` | the public JSON endpoint, asked with a GET |
| `description` | one sentence for the Details tab and the pages that name the lists, saying nothing about the voter is sent |
| `read` | the adapter: the endpoint's JSON to candidates in an endorsement file's shape, raising `ValueError` for an answer it can't read |
| `headers` | any headers the endpoint needs, or `None`; never a key |
| `token` | `None`, or a reader of `url`'s page that returns the headers to send `api`, for a token the site rotates |

What each site does:
- **Muslims United PAC:** `/api/public/endorsements` is an object of categories (`incumbents`, `challengers`) beside counts, which are skipped. Its `jurisdiction` (`federal`, `state`, `local`) is no county.
- **Emgage PAC:** `/api/v2/donation-page/SupportOurCandidates` answers HTTP 500 without the `RequestVerificationToken` header from its donation page's meta tag (no cookie needed). The page and token are never stored. `district` packs party, state and number ("D-TX-35", "I-VT"). Most notes are an image only. It still lists Greg Casar for TX-35, his seat before the 2025 redistricting.
- **CAIR Action:** `cairactionguide.org/api/endorsements` (asked with `accept: */*`) has one endorsement per candidate and election, so a primary and its runoff are folded into one entry. Only "Endorsed", "Preferred" and "Joint Endorsement" count; CAIR keeps candidates who lost, and so does Pallot. A local office's name may start with its county ("Fort Bend County Commissioner Pct 4"). The site has no page per candidate, so `url` is `/explore#state-tx`.

To add a feed:
1. Write its adapter beside `muslims_united` and append its `Feed` to `FEEDS`.
2. `uv run python scripts/record_fixtures.py --only endorsement_feeds`, which `Upstream` serves (a feed with a `token` also keeps its page's meta tags, with the token replaced by `recorded-token`).
3. Tests in `tests/test_endorsement_feeds.py` (the adapter over the fixture, and a Texas candidate matched on a ballot), and the feed's id in `test_api.py`'s and `test_ballot.py`'s lists of every source.
4. Look an address up twice (the second makes 0 external calls), and check Settings, `pallot-cache hard-refresh --only <source>`, About, Privacy and the FAQ.
5. Bundle it only once the organization agrees (`PERMITTED` in `bundles/endorsement_feeds.py`).

## Bundled snapshots

Two kinds come with Pallot (README's "Bundled snapshots" says what's in them):
- **Snapshot packages** (`trackaipac_cache/`, `voteforpeace_cache/`, `tec_cache/`), copied into `data/` on first run. `pallot-cache hard-refresh` refreshes them; `rebuild --reset-snapshots` goes back to the repo's copy. Each package's own README says how to update the bundled copy (`uv run <package> refresh`). `trackaipac_cache` is a copy of the maintainer's library (`Fahd-Siddiqui/TrackAipacCache`): see AGENTS.md before changing it. TEC's refresh runs in its own process, since it reads a couple of GB of CSV.
- **Cached answers** (`bundles/`), seeded into the cache at startup, dated when they were last checked, where the cache has no newer copy. A lookup asks live only once a bundled answer is older than its bundle lifetime. Files are one answer per line, sorted, so a diff shows each changed answer; they never hold a key or a header. Once seeded, only each bundle's count and date stay in memory, for `pallot-cache check`'s "Came with N answers".

To bundle a source's answers:
1. Write its builder: an `async def build(ctx: Context) -> dict[str, int]` that makes a lookup's requests through `ctx.cache` with the source's own class, and raises `BundleError` if any failed.
2. Add a `Bundle("<source>", build, "daily" or "weekly")` to `registry.BUNDLES` (with `include`/`keep`/`lifetime` when it needs them), and a `<source>_bundle` field to `Ttls`, at least its cadence plus a day, with `.env.example`.
3. Give its counts labels in `stats.BUNDLES`.
4. Run `uv run pallot-bundle refresh --only <source>` once and commit `bundles/data/`.

## GitHub Actions

- `tests.yml` checks every pull request (stacked ones too) and every push to `develop`; a change to Markdown only skips it. pytest runs on Python 3.10 with `uv sync --locked`, so `pyproject.toml` changed without `uv lock` fails. The Docker job builds the image when `Dockerfile`, `compose.yaml`, `.dockerignore`, `pyproject.toml` or `uv.lock` changed.
- `live-tests.yml` runs `pytest -m live`, only when started by hand from the Actions tab. It uses the `PALLOT_FEC_API_KEY` secret.

### The daily refresh

`refresh-caches.yml` refreshes every snapshot each day (09:17 UTC) until 2026-11-15; after that its first job skips the rest, and the workflow should be disabled.
- It runs on `chore/refresh-caches`, with `develop` merged in first (or a new branch from `develop`). If that merge conflicts, merge `develop` into the branch by hand, or delete the branch, and run it again.
- It runs `pallot-bundle refresh --due`, the three snapshot packages' refreshes, then `pallot-bundle stats --since HEAD --readme README.md`, which rewrites README's "What the snapshots hold". Each step goes on after an error. If anything changed, it runs the tests, then pushes one commit to `chore/refresh-caches`. The maintainer opens and squash-merges the pull request into `develop`, then deletes the branch.
- Secrets: `PALLOT_FEC_API_KEY` to `PALLOT_FEC_API_KEY3` (required for the FEC's refresh); optional `PALLOT_REFRESH_TOKEN` (Contents read/write), without which pushes don't start other workflows.
- If its push is refused because a workflow file changed on `develop`, merge `develop` into `chore/refresh-caches` yourself and push, or delete the branch.

## Docker image

- The `Dockerfile` installs Pallot as a regular (not editable) package from `uv.lock`, without the dev tools, so static files and snapshots reach the image only as package data (`[tool.setuptools.package-data]`).
- `.dockerignore` keeps `.env`, `data/`, the tests and scripts out, but lets in the few `.git` files that name the commit, which the build writes into the package for the footer.
- Everything Pallot writes goes under `PALLOT_DATA_DIR` (`/data` in the container).

## Releases

- The version lives in `__version__` in `pallot/__init__.py`; `pyproject.toml` reads it.
- Bump it in a pull request into `develop` (`feat: release vX.Y.Z`). Once merged, tag the merge commit with an annotated tag, push the tag, and publish the release from it:

```bash
git switch develop && git pull
git tag -a vX.Y.Z -m "Pallot X.Y.Z"
git push origin vX.Y.Z
gh release create vX.Y.Z --verify-tag --title "Pallot X.Y.Z" --notes-file NOTES.md
```
